# 서버 권위 멀티플레이 환경 구현 방향성 참고 문서

- 성격: 서버-클라이언트 아키텍처 구현 방향성 문서.
- 상세: 세부 구현(클래스 구조, 메시지 필드, 수치)은 포함하지 않으며, 각 단계 착수 시점 제안하고 확정한다

## 1. 배경과 목적

- **서버 권위(Server Authority, 서버가 게임 결과를 최종 확정하고 클라이언트는 입력만 보내는 구조)** 계열
- 목적
  - 포트폴리오에서 **서버 구조**를 어필하는 것이 목적이다
  - float 기반의 수학 함수와 연산을 그대로 쓸 수 없어, 수학 연산을 직접 구현하고 검증하는 부담이 크다. 서버 권위에서는 서버 결과가 정답이라 float 오차를 보정으로 흡수할 수 있으므로 이 부담을 없앤다
- 목표 수준: 신입 포트폴리오에서 현실적으로 완성 가능한 범위

## 2. 범위

### 1순위 포함
- 헤드리스 서버(Headless Server, 화면 없이 돌아가는 전용 서버)가 이동과 피격 판정을 확정
- 1:1 룸(Room, 두 플레이어가 들어가는 방) 매칭
- 상대 캐릭터를 **스냅샷 보간**(Snapshot Interpolation, 받은 상태 사이를 이어 붙여 부드럽게 표시)으로 표시
- 내 캐릭터 **이동 한정** 클라이언트 예측(Client-Side Prediction, 서버 응답을 기다리지 않고 먼저 움직여 보여 주는 것)
- **보정**(Reconciliation, 서버 결과와 어긋나면 서버 기준으로 되돌리고 다시 계산)
- 호스트 모드: 방을 개설하면 별도 프로세스의 전용 서버가 자동으로 실행되는 구조

### 2순위 포함
- 지연·유실을 일부러 만드는 테스트 도구와 상태 표시 화면(HUD)
- 내 캐릭터 **공격 모션 시작 예측**(Attack Start Prediction): 시작만 먼저 보여 주고, 타격 결과(맞았는지·데미지·경직)는 서버가 확정한 뒤 표시한다. 이동 예측·보정이 안정된 뒤에 확장한다

### 제외
- 래그 보상(Lag Compensation, 상대 상태를 과거로 되감아 판정하는 기법)
- 롤백(Rollback, 과거 시점으로 돌아가 다시 시뮬레이션하는 네트워크 방식)
- 다중 서버·확장성, 인증·DB
- NAT 통과·릴레이(NAT Traversal·Relay, 공유기 너머 외부망 접속을 자동화하는 기능)

## 4. 원칙

- 클라이언트 입력은 신뢰하지 않는다. 입력은 "의도"만 전달하고, 결과는 서버가 계산한다
- 서버 코드에서는 Unity API(로그, 수학 함수 등)를 쓰지 않는다
- 서버와 클라이언트는 같은 프로세스·스레드(Thread, 프로세스 안의 실행 흐름)에서 섞지 않는다. 호스트 모드의 호스트 플레이어도 일반 클라이언트처럼 서버에 접속한다
- 전송 계층(Transport, 데이터를 실제로 주고받는 부분)은 인터페이스로 감싸서, 메모리 안 전송과 실제 소켓 전송을 바꿔 끼울 수 있게 한다.
  - 전송 라이브러리는 **LiteNetLib**을 쓰고, 라이브러리는 전송 계층으로만 사용하며 예측·보정은 직접 구현한다(CLAUDE.md의 기존 원칙 유지)
- 공격 모션 예측은 "시작은 예측, 결과는 서버 확정"으로 나눈다. 서버가 거부하면 서버 기준으로 되돌린다
- 단계마다 눈으로 확인할 수 있는 완료 조건을 둔다.
  - 앞 단계의 완료 조건을 통과하기 전에는 다음 단계의 코드를 쓰지 않는다

## 5. 방향성 이탈 점검 기준

- 래그 보상·롤백·확장성·NAT 통과 등 제외 범위 항목을 구현하려 하지 않는다
- 전송 계층이나 프로토콜의 최적화(데이터 압축 등)는 어필 효과 대비 부담이 크므로 후순위로 둔다
- 한 단계의 완료 조건을 통과하면 품질이 'good enough'일 때 다음 단계로 넘어간다
- 지엽적인 완성도(보간 품질, 연출 등)에 시간이 쏠리지 않는지 단계 종료 시마다 확인한다

## 6. 결정 사항과 미정 사항

### 확정
- 공격 모션 시작까지 클라이언트 예측에 포함한다(C9, 2순위). 시작은 예측하고 결과는 서버가 확정한다
- 전송 라이브러리는 **LiteNetLib**이다. 순수 C#이라 서버를 Unity 없이 .NET 콘솔 프로그램으로 구동할 수 있고, 전송만 제공하므로 예측·보정을 직접 구현한 부분이 드러난다
- 서버 형태는 **별도 프로세스의 전용 서버**이며, 호스트 모드는 그 서버를 대신 실행해 주는 런처다. 외부 PC 접속은 호스트 PC의 포트 개방(Port Forwarding, 공유기에서 외부 접속을 내부로 연결해 주는 설정)이 필요하며, 시연은 로컬·같은 네트워크를 기준으로 한다

### 미정 (해당 단계 착수 시 구현부가 제안)
- 호스트 모드에서 정해 둘 규칙: 서버 프로세스 수명 관리(클라이언트가 비정상 종료해도 서버가 남지 않게 하는 방법), 서버 준비 완료 신호, 포트 선택과 충돌 시 처리
- 공격 모션이 서버에서 거부됐을 때의 되돌림 연출 방식
